# heund.net: SEO and AI discoverability audit

Audit date: 19 October 2026. Final patch base: `efb50283e7e2f06dbcef31d0350e49c7ddbe45d8` in `heund/web_test1`.

The main obstacle is the relationship between URLs and content. The terminal interface can remain a single-page experience, while each public URL serves a complete, independently readable HTML page. That is the central change in this patch.

## Scope and confidence

Reviewed the public HTTP responses, repository routing, content loading, navigation, language switching, metadata, sitemap, robots directives and public search results. Checked official Google, OpenAI, Perplexity and Vercel guidance. No Search Console, Bing Webmaster Tools, analytics reports or verified crawler logs were available. Consequently, this is a technical and public-discovery audit, not a measurement of total indexed pages, rankings, AI citations or conversion performance.

The repository changed during the audit. The patch was rebased onto `efb5028`, preserving the expanded Munjeon text, corrected Biennale titles and media, revised ISEA citation and abstract, restored related-work links, and the decision to keep ISEA in the research overview. It does not recreate the removed ISEA detail page. Earlier observations from `e331f6a` were rechecked against the newer live deployment.

## What the live site currently does

| Observation | Evidence | Consequence |
| --- | --- | --- |
| Clean routes return the same shell | `/`, `/research/overview` and `/research/bdss` each returned the same 63,304-byte HTML response; SHA-256 `9dd4d6d15e1e3ce3f9f7e851b38dc74d2be50d1f5243f270b9682c39eba57217` | A direct request does not identify the requested research page through its body or metadata. |
| Initial main content is empty | `#content` and the mobile content container contain comments until JavaScript fetches a fragment | Reading the initial HTML misses the work and research narrative. Google can render JavaScript, but that does not make the current initial response or all other retrieval systems equivalent to a full page. |
| Canonical and social metadata always describe home | Clean research routes return the homepage title, description, canonical and Open Graph URL | Canonical signals conflict with treating individual works and research topics as distinct pages; shared links also lose page-specific context. |
| Navigation is implemented as clickable `div` elements | Sidebar `.nav-item` elements have `data-file`, without `href`; path adapter and navigation use hash fragments | Discovery depends on script execution. These are not ordinary crawlable links. |
| Language changes are browser state | English and Korean hreflang values both point to `/`; the toggle changes DOM visibility | There is no independently addressable Korean version for each page. |
| Sitemap exposes fragments | The current sitemap has 12 URLs: home plus 11 raw exhibition/research fragments | The workaround makes text available, but those fragments lack complete document metadata and the portfolio shell. About and contact are absent. |
| Removed ISEA route now returns 404 | `/research/isea-2026` returned 404 after the author's consolidation | Previously shared links need to reach the research overview. |

The existing workarounds are useful: the fragments contain substantial text and the sitemap is reachable. They do not yet connect discovery, canonical identity, language and the visual application into one consistent public page system.

Existing strengths include HTTPS, redirection to the `www` host, a public robots file, a reachable sitemap, descriptive research prose, and an actual 404 for an arbitrary nonexistent URL. The patch retains these properties.

## Search and AI visibility

Public searches for `site:heund.net "Hee-Eun Kim"`, the exact ISEA paper title within the domain, and `"Hee-Eun Kim" "BDSS"` surfaced the homepage in the returned sample. The extracted homepage text was largely interface furniture: terminal labels, experiment filenames and viewer labels. The sample did not establish coverage of the individual research pages. Search tools may broaden a query or omit results, so this is not evidence that only one page is indexed.

There are also other people with the same romanised name in public results. Consistent association of Hee-Eun Kim, 김희은, heund, the artist's own work and the social profiles already linked by the portfolio should help disambiguate the entity. No unrelated profiles were added.

For Google AI Overviews and AI Mode, ordinary crawlability, indexing eligibility, textual content and internal links remain the foundation. Google does not require an AI-specific text file or special schema. For ChatGPT search, OpenAI identifies `OAI-SearchBot` separately from the training crawler `GPTBot`; Perplexity similarly documents its search crawler. The existing wildcard robots policy permits these public pages. That does not prove that the hosting firewall accepts requests from actual crawler IPs, or that a page will be selected as a citation.

This patch therefore improves the same complete public pages for people, search engines and text retrieval. It does not introduce user-agent-specific content or change AI training permissions. An `llms.txt` file is not included: it would not address the observed empty-body, canonical or linking problems, and no citation or ranking improvement is assumed from adding one.

## Priorities and implemented changes

| Priority | Change | Result |
| --- | --- | --- |
| P0 | Generate full HTML for every current route | 14 English pages plus 14 Korean pages contain the actual authored content in their first response. |
| P0 | Replace home rewrites and the path-to-hash adapter | Clean URLs remain in the address bar; History API navigation retains the interactive interface. |
| P0 | Generate unique metadata | Each route has its own title, description, self-canonical, Open Graph/Twitter metadata and reciprocal language alternates. |
| P0 | Expose real links | Sidebar entries, titles and relevant research links are anchors. Modified clicks and new tabs retain normal browser behaviour. |
| P1 | Allow rendering resources | The three runtime script exclusions are removed from robots.txt; the `/folders/` exclusion remains. |
| P1 | Create `/ko` and `/ko/...` versions | Language switches have shareable destinations, and back/forward navigation restores language and content. |
| P1 | Consolidate old URLs | Legacy fragment URLs permanently redirect to complete pages. Removed ISEA URLs lead to the research overview. Old `/#...` bookmarks resolve in the enhanced app. |
| P1 | Replace the sitemap | `dist/sitemap.xml` lists only the 28 canonical pages. No fabricated build-date `lastmod` values. |
| P1 | Separate runtime fragments from public pages | `/_fragments/*.txt` supports in-page loading and receives `X-Robots-Tag: noindex`. It remains crawlable so the directive can be read. |
| P1 | Add stable entity identifiers | Person, WebSite and WebPage/ProfilePage JSON-LD identify the artist and each page, using only the existing Instagram and YouTube profiles. |
| P1 | Make the introduction textual | A concise visible artist introduction and exhibition/research links accompany the existing canvas. |
| P1 | Keep the fallback usable | Content and links remain readable without JavaScript on desktop and mobile. The same authored content powers both render paths. |
| P2 | Reduce irrelevant snippet candidates | Experiment windows and command/viewer furniture receive `data-nosnippet`; public content remains eligible for snippets. |

The build uses Node and a pinned development-only HTML parser. It adds no application server and no client-side framework. Existing exhibition and research fragments remain the content source. About, contact and the introduction move into shared templates, removing duplicate about markup from the application script. The public email already shown by the site is also available in the static contact page.

The ISEA presentation remains explicitly forthcoming as at 19 October 2026. No DOI, actual publication date, exact presentation date or newly inferred research results are added. The author’s forthcoming citation and proceedings link are retained. The current exhibition copy and Jeju poster are preserved.

The existing `/videos/*` header incorrectly forced all files in that directory to `video/mp4`, including image assets. The patch retains the CORS header and lets the static host choose the appropriate MIME type.

## Follow-up improvements

1. **Verify production indexing.** After deployment, submit the new sitemap in Search Console and Bing Webmaster Tools. Inspect English and Korean research overview, BDSS, exhibitions overview and one individual work. Check the fetched HTML, selected canonical and indexing result; do not infer acceptance from sitemap submission alone.
2. **Connect authoritative references when available.** Add verified organiser, exhibition or proceedings links to the relevant existing sections. Use confirmed publication metadata and an authorised manuscript or abstract when available. Preserve the forthcoming status until the presentation occurs. The newly authored ISEA abstract and Munjeon description are already useful substantive additions.
3. **Measure media performance separately.** The repository contains substantial image and video assets, but repository size is not page transfer size or a Core Web Vitals result. Check PageSpeed Insights/Search Console field data and representative mobile pages. Based on those measurements, optimise oversized images, specify image dimensions, avoid unnecessary video preloads and load only the active media/language where practical. Media compression and playback changes are outside this patch.
4. **Check genuine crawler access.** Use hosting logs and the providers' published verification/IP guidance to investigate real bot failures. A successful request with a spoofed crawler user-agent is insufficient evidence, and should not become a blanket firewall bypass.
5. **Track outcomes.** Record a pre-deployment baseline where available, then compare equivalent 28-day periods for indexed canonical pages, organic impressions, non-brand query coverage and visits to research/work URLs. Review brand queries in both languages, BDSS/RCS, artwork names, Munjeon/Jeju and the exact paper title. AI referrals can be tracked when a click supplies a referrer; analytics cannot measure every citation or zero-click answer.

## Verification and remaining limits

The automated suite checks all 28 initial documents, unique titles, canonicals, reciprocal hreflang, social URLs, semantic headings, substantive text, localised navigation, parseable JSON-LD, ISEA title/status, exact sitemap membership, redirects, fragment noindex and genuine 404s. It has 31 passing tests.

Chromium checks cover 1440×1000 desktop and 390×844 mobile, with JavaScript both enabled and disabled. They exercise the research overview, Korean BDSS, exhibition overview, Resonance Loop and home; enhanced checks also cover language switching, the contextual BDSS link, sidebar/mobile navigation, back/forward, legacy hash navigation, about and contact. A simulated fragment-service failure also verifies that navigation and language switching fall back to full static pages. Screenshots were inspected and a mobile fallback layout defect was corrected. External analytics and media transfers were stubbed during browser checks: these results do not establish video playback, third-party analytics delivery or production performance.

Local preview emulates this project's Vercel static routing. The actual Vercel deployment, bot firewall, production redirects, search indexing and AI citation outcomes still require post-deployment checks. This patch has not been deployed.

## Implementation follow-up

Review against the deployed source identified five legacy aliases intercepted by Vercel clean-URL redirects, About heading visibility/size regressions, query stripping, an abandoned canvas animation loop, and stale asynchronous history navigation. The implementation corrects these, pins Node 22.x, adds existing per-work sharing images, and reserves a separate introduction area below the canvas. Focused regression checks now cover those navigation and lifecycle cases, complete legacy redirect chains, and exclusion of local audit material. Initial static videos have native controls; interactive fragments retain the existing custom players.

The original browser evidence above belongs to the supplied patch. It does not constitute browser verification of the corrected implementation. Deployment HTTP checks and any unavailable browser checks must be recorded separately.
